# Release v0.12.0

## Overview

v0.12.0 turns Gateway plugins into MDK apps. An app runs in its own `@tetherto/mdk-app-runtime` process, the Gateway forwards
requests to it over HRPC and runs no app code, and a stack lists its apps under `spec.apps`. Apps can also ship a UI that the
operator shell loads at runtime.

The release closes the stack by default. Kernel and Workers admit only allowlisted keys, with `read`, `write` or `admin` roles,
the Gateway ships with a Host allowlist, rate limiting and security headers, and a broad hardening pass covers queries, device
addresses, secrets and the Kernel protocol.

The Kernel also stops guessing about commands: it never re-sends one it cannot confirm, and a command can declare how to verify
that the device reached the requested state.

## Breaking changes

**Gateway plugins become apps.** `startGateway({ extraPluginDirs })` and `spec.gateway.plugins` are rejected; declare apps with
`apps` and `spec.apps`, and create them with `mdk create app`. App routes mount under `/apps/<name>` unless `mount: '/'` is set.
`@tetherto/mdk-plugins` and its bundled plugins are removed, and the agent and demo packages become `@tetherto/mdk-app-agent`
and `@tetherto/mdk-app-demo`.

**An empty allowlist admits nobody.** Kernel, Worker discovery and Workers are fail-closed. Allowlist the Gateway, MCP server,
CLI and app runtime keys, or run them on one machine and let the trusted-keys directory admit them, and give each Worker the
Kernel's client key as `allowedKeys`.

**Unconfirmed commands are not retried.** They settle as `TIMEOUT` with `ERR_COMMAND_UNCONFIRMED`, and `commandMaxRetries` is
removed.

**Tighter defaults.** The Gateway no longer trusts proxies or serves `GET /echo`, `auth: true` routes need an `authVerifier`,
the Kernel and Gateway no longer install signal handlers unless `handleSignals: true`, and backend packages close deep imports
behind an `exports` map.

**`@tetherto/mdk-react-devkit` drops the Pool Manager, Explorer, Reporting tool, vendor container widgets, Inventory and
Repairs, the page-level `Alerts` and `ContainerDetail`, and the utils, constants and types nothing used** (779 exports), and **`@tetherto/mdk-react-adapter` drops
every data hook that called a route no MDK backend serves** (335 exports), with the `@tetherto/mdk-ui-foundation/presets/mining`
entry point and the device-action builders behind them. Apps read their own Gateway routes with `useQuery`; `gatewayRedirectAuth` and the device tag helpers
now import from `@tetherto/mdk-ui-foundation`.
Its primitives are unchanged. The full list of breaking changes and migration steps is in [`CHANGELOG.md`](../../../CHANGELOG.md).

## What's new

**`@tetherto/mdk-app-runtime`**: hosts one app per process behind the Gateway, with its own key allowlist.

**App UIs in the shell**: an app's `ui/index.js` built with `defineMdkApp` adds pages under `/app/<name>/` and home-page panels
to the operator shell, using the new app hooks in `@tetherto/mdk-react-adapter`.

**Command verification**: a contract command can declare `verify`, and the command status reports whether the device was seen
in the requested state.

**CLI**: `mdk add app|worker` installs an app or Worker from npm or GitHub, `mdk validate app|worker` checks one (with
`--smoke` for Workers), `mdk create app` scaffolds one, and `mdk run app` runs one. MCP write tools are opt-in with
`--allow-write`.

**Skills**: `mdk-create-app` and `mdk-publish-security` join the skill suite.

**Workers**: Antminer support moves to the manufacturer's `antminer-mdk-worker`, and the `mvp-site` example runs it alongside
external pool Workers.

## Removed

`examples/full-site`, `examples/backend`, the sample demo Worker and the CLI's stub commands (`mdk get`, `describe`, `logs`,
`discover`, `mcp register`, `manifest`) are removed. `examples/mvp-site` is the runnable example.

## Security

Stats keypaths no longer go through `new Function`, remote device registration refuses loopback, link-local and metadata
addresses, secrets are redacted from device and pool config, reads and time ranges are bounded, and a Worker may only write to
the devices it owns. Dependency floors clear GHSA-238p-pmpm-9mq7, GHSA-6qxp-vccf-f47h, GHSA-f23p-vx2j-j53r and
GHSA-68fv-2mgg-jv7q.

## Fixed

**`wrong_miner_pool` checks the pool URLs**: it compares each configured pool with the one the miner reports, instead of firing
only when a list was empty.
