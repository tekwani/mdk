# Release v0.8.0

## Overview

v0.8.0 is primarily an **agent** release. In v0.7.0 the operator agent arrived as a runtime and a Gateway plugin; here it becomes
something an operator actually looks at, and something a maintainer can hold to a standard:

- **The agent gets a face**: `@tetherto/mdk-ui-agent` renders the agent plugin's event contract as a conversation, and drops
  into any MDK shell as a single `<CoPilot />`. Its headless half is a separate entry point, so a host that wants its own chat
  surface can take the transport, the turn reducer and the conversation store without the components.
- **The agent gets a standard**: Its standing instruction becomes a versioned module, and that version is recorded with every
  eval run — so two battery scores taken weeks apart are comparable. The instruction itself is now mostly about what
  the agent must *not* do.
- **The agent gets a choice of model**: An OpenAI-compatible provider sits beside the local one, with request pacing,
  rate-limit retries and API-key redaction. The local provider stays the default; nothing becomes remote unless asked, and
  picking a hosted endpoint prints a startup warning naming the host that prompts and tool results will reach.

The following changes need attention if you depend on them:

- The sample site's MCP tools renamed result fields
- The `mdk onboard` picker no longer offers a hardware Worker
- The in-repo Whatsminer Worker package is now externally maintained

## What's new

- **`@tetherto/mdk-ui-agent`**: the operator agent as a drop-in. `<CoPilot />` for the docked panel, `ChatUIEntry` for a
  full-page route, and `@tetherto/mdk-ui-agent/core` for the headless contract — event and turn types, SSE transport, turn
  reducer, conversation store, with no React. It reaches for browser globals (`fetch`, `localStorage`, `crypto`) behind a
  guard or injectable, and `TextDecoder` directly, since it's available in both a browser and Node — so it runs outside a
  browser but is not unaware of one. The panel loads behind a lazy boundary so the markdown renderer and
  syntax highlighter stay out of the host's first paint.
- **A versioned agent charter**: the system prompt sent on every request is now a pinned module carrying its own version.
  Because the charter is the shared prefix the prompt cache is keyed on, its text is pinned by tests — reflowing a line would
  cost every live session its warm prefix.
- **An OpenAI-compatible hosted provider**, selected with `--provider`, `--base-url`, `--api-key`, `--model`, `--rpm` and
  `--capability`. The API key is redacted at the transport, rate limits are absorbed with `Retry-After`-aware retries rather
  than surfaced, and the local provider's readiness poll now backs off instead of retrying on a flat interval.
- **`@tetherto/mdk-plugin-demo`**: a Gateway plugin over the sample Worker, serving fleet totals
  (`GET /api/demo/summary`) and recent history (`GET /api/demo/history`), both declared read-only in the plugin manifest with
  schemas, examples and error codes. A missing Kernel client is reported as a `kernelConnected: false` response rather than an
  error.
- **Generated-page freshness**: `npm run regenerate-docs` rewrites every page written by a script, `-- --check` reports what
  is stale without touching anything, and the `docs-freshness` workflow annotates pull requests instead of failing them when a
  page is stale. A contract can land in one change and its regenerated page in the next without failing CI. A broken
  generator or a skipped target does still fail the job.
- **The shell template ships the agent mounted** once in the layout rather than on a route, so it survives navigation, with
  the dev server proxying `/agent` to the Gateway. The component catalog gained an *Agent Co-pilot* page driven by a scripted
  gateway, so the surface can be explored without a live agent.
- **A demo-site quickstart in the README**: clone, `npm run setup`, `node start.js --miners 3`, with the boot lines to wait
  for and the port each surface lands on.

## Changed

- **A turn has a declared budget, and the default one grew**: Steps and output tokens are now set by `--capability` — small,
  mid or large — and the default local budget is four times the output tokens it was. A hosted provider defaults to large.
  Nothing is inferred from the model name, so a bigger local model has to say `--capability mid`.
- **Prose is held back until a tool has returned**, and an answer stating a figure the tools did not supply is re-prompted
  rather than shown. This is what closed the invented-device failure mode.
- **A Gateway plugin route that omits `safety` now needs approval**: Previously an unannotated route was judged by the verb in
  its name, so a `get_*` or `list_*` route ran ungated. It is now treated as a write and stops at the human-approval gate.
  If you maintain a plugin, declare `safety: "read-only"` on the routes that only read. Approval also honors a route that
  states only `destructiveHint`.
- **The tool loop polices the model's output instead of forwarding it**: Replies that echo the question, attempt an unreadable
  tool call, or state a figure the tools did not supply are retried; one that still names a tool or restates the prompt is
  replaced with a fixed apology rather than shown. Repeated identical calls are caught by fingerprinting the tool and its
  arguments. Answers that hit the token ceiling say so, the final step is told it is final, and every model request now
  carries a deadline.
- **The in-repo Whatsminer Worker is replaced by MicroBT's own externally maintained `whatsminer-mdk-worker`**, a
  bare `mdk-contract.json` plus handlers which you  [host yourself on `WorkerRuntimeV2` through a small adapter](../../guides/miners/run-whatsminer-worker.md).
- **The sample site's MCP tools were rewritten for how a small model reads them**: `summarize_site` glues every count to the
  noun it counts and spells zero as a word; `act_device` now reports an explicit outcome rather than leaving a caller to infer
  success from the absence of an error. Every tool but `count_devices` renamed result fields in the process — `ref`,
  `attr`/`value`, `items`, and a `totals` wrapper — so anything reading those results by key needs updating. The changelog
  itemizes them.
- **`mdk onboard` offers the `demo-worker` sample** as its bundled Worker, so scaffolding exercises a device model written for
  plugin authoring rather than a specific firmware. Other entries left the picker to make room for it — see the changelog's **Removed** section.
  The picker no longer offers a hardware Worker; point a spec entry at `backend/workers/miners/antminer` by hand to keep using the Antminer Worker.

## Fixed

- **A root `npm install` broke the agent Gateway plugin**: the standalone core packages were not reachable from the root
  `node_modules`, so the plugin failed to load. They are linked into place now, and the link survives a reinstall.
- **A device the model invented answered like a real but quiet one**: `get_device` now confirms the reference against current
  site status and says plainly when it is not there.
- **A rejected write could read as a success**, because the Kernel signals rejection in a field rather than by throwing and
  that field can be empty. The `act_device` tool now checks whether the field is present rather than whether it is truthy.
- **The full-site control page cleared its spinner before the refreshed state arrived**, briefly showing the pre-command power
  mode beside an idle control.

## Security

- **The agent's API key is read from the environment first**: `--provider openai` takes `OPENAI_API_KEY` and every other
  endpoint takes `MDK_AGENT_API_KEY`; `--api-key` still works but is the fallback, because an argument is visible to other
  processes via `ps` and lands in shell history.
